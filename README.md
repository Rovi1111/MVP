# Учёт расходов (MVP)

Веб-сервис для анализа расходов организации: загрузка факта и бюджета из Excel/CSV,
анализ динамики расходов за год-два на диаграмме «факт и бюджет», AI-анализ через локальную Ollama,
отчёты в PDF и Excel. Полная постановка — в [SPEC.md](SPEC.md) (согласованные уточнения — в разделе 14).

## Установка на macOS с нуля

```bash
# 1. Homebrew (если ещё нет)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 2. Python 3.12 и Ollama
brew install python@3.12 ollama

# 3. Зависимости проекта
cd <папка проекта>
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt      # для работы без тестов хватит requirements.txt
```

С [uv](https://docs.astral.sh/uv/) вместо шага 3: `brew install uv && uv venv --python 3.12 && uv pip install -r requirements-dev.txt`.

### Модель для AI-анализа

Ollama запускается нативно (не в Docker: в Docker на Mac нет доступа к GPU).

```bash
ollama serve            # в отдельном окне терминала; либо запустите приложение Ollama
ollama pull llama3.1
```

Сервис работает и без Ollama — недоступен будет только AI-анализ.

## Настройка

```bash
cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"   # вставьте результат в SECRET_KEY
```

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | По умолчанию SQLite `./data/app.db`. Для PostgreSQL: `postgresql+psycopg://user:pass@host/db` и `pip install "psycopg[binary]"` — код менять не нужно |
| `SECRET_KEY` | Ключ подписи сессий и CSRF-токенов. Обязательно свой |
| `COOKIE_SECURE` | `true`, если сервис открыт по HTTPS |
| `OLLAMA_URL`, `OLLAMA_MODEL`, `OLLAMA_TIMEOUT` | Значения по умолчанию; администратор меняет их в разделе «Настройки» |
| `SMTP_*` | Почтовый сервер для отправки отчётов; также задаётся в «Настройках» |

## Запуск

```bash
alembic upgrade head                                           # создать/обновить схему БД
python -m app.cli create-admin --org "Моя компания" --login admin   # пароль спросит интерактивно
python -m app.cli seed                                         # необязательно: демо-данные
uvicorn app.main:app --port 8000
```

Откройте <http://localhost:8000>. REST API описан в Swagger: <http://localhost:8000/api/docs>.

`create-admin` создаёт организацию, если её ещё нет. Остальных пользователей администратор
или руководитель добавляет в разделе «Пользователи».

### Вход в систему

1. Откройте <http://localhost:8000> — откроется форма входа.
2. Введите логин и пароль. Свой администратор создаётся командой `create-admin` (выше);
   демо-пользователи — командой `seed` (ниже).
3. После входа вверху видны разделы, доступные вашей роли. Кнопка «Выйти» — справа вверху.

Если пароль забыт, администратор или руководитель задаёт новый в разделе «Пользователи»
(поле «Новый пароль»). Если забыт пароль единственного администратора — создайте ещё одного
командой `create-admin` с другим логином и той же организацией. Сессия живёт 12 часов;
после смены пароля все прежние сессии пользователя завершаются.

Чтобы открыть сервис коллегам в локальной сети, запустите его с `--host 0.0.0.0`
и дайте им адрес `http://<IP вашего компьютера>:8000`.

### Демо-данные

`python -m app.cli seed` создаёт организацию «Демо-компания» с обычными статьями расходов
(закупки, зарплата, аренда, маркетинг, логистика и т. п.), фактом по дням и помесячным
бюджетом за 2024–2025 годы.
Логины: `demo_admin`, `demo_manager`, `demo_employee`. Пароль — константа `DEFAULT_PASSWORD`
в [app/seed.py](app/seed.py) либо свой: `python -m app.cli seed --password <пароль>`.
В данных есть рост и снижение по статьям, появившиеся и исчезнувшие статьи, превышения бюджета.

Файлы для ручной загрузки лежат в [samples/](samples/) (создаются `python scripts/make_samples.py`).

## Как пользоваться

1. **Ввод данных** — перетащите файл факта или бюджета (XLSX, XLS, CSV) либо введите строки
   формой или JSON. Сервис покажет ошибки по строкам или предпросмотр; данные записываются
   только после подтверждения.
2. **Сопоставление статей** — если статьи из файла нет в справочнике, руководитель или
   администратор выбирает для неё категорию или создаёт новую. Выбор запоминается.
3. **Анализ расходов** — динамика за длительный период на одной диаграмме: фактические
   расходы столбцами с накоплением по статьям и линия бюджета. Период задаётся быстрыми
   кнопками («12 месяцев», «24 месяца», «Текущий год», «Прошлый год», «Все данные») или датами
   «с — по»; шаг — дни, месяцы, кварталы или годы. Фильтры: статьи расходов и версия бюджета.
   Диаграмма обновляется сразу при изменении фильтра; её можно скачать в PNG.
4. **AI-анализ** — кнопка под диаграммой: заключение о динамике за выбранный период
   (тренд по месяцам, рост и снижение по статьям, отклонения от бюджета).
5. **Сохранённые анализы** — просмотр, экспорт в PDF/Excel, отправка на email.

Разделы выбираются в меню слева; после входа сразу открывается «Анализ расходов».

### Шаблоны Excel

Шаблоны формируются на лету, файлов в репозитории нет:

- в интерфейсе — ссылки «Скачать шаблон Excel» на странице «Ввод данных»;
- по API — `GET /api/templates/fact` и `GET /api/templates/budget`;
- код — [app/services/excel_templates.py](app/services/excel_templates.py).

Колонки: `Период`, `Статья`, `Сумма`, `ЦФО` (необязательна). Распознаются синонимы
на русском и английском (список — `COLUMN_SYNONYMS` в [app/datasources/excel.py](app/datasources/excel.py)).

### Правила работы с данными

- **Периоды.** Данные хранятся по дням. Период в файле: дата (`15.01.2025`, `2025-01-15`),
  месяц (`2025-01`, `01.2025`, `янв 2025`) или квартал (`2025-Q1`, `1 кв 2025`). Сумма за месяц
  или квартал ставится на первый день периода и не размазывается по дням.
- **Повторная загрузка факта** заменяет весь действующий факт за календарные месяцы, которые
  есть в файле (включая ручной ввод за эти месяцы); прежние записи остаются в истории.
  Ручной ввод факта данные только добавляет.
- **Бюджет** — каждая загрузка создаёт новую версию-снимок. Ручной ввод бюджета создаёт
  версию «последняя версия + введённые строки». Квартальная строка бюджета на диаграмме
  делится на три месяца поровну; при шаге «дни» линия бюджета не показывается.
- **Суммы** — в рублях с копейками. Отрицательные суммы (сторно) допустимы в факте, но не в бюджете.

## Как добавить новый источник данных

Вся обработка после чтения (валидация, суммирование дублей, сопоставление статей,
версии, аудит) не зависит от источника. Чтобы подключить банк, 1С или эквайринг:

1. Создайте класс в `app/datasources/`, унаследованный от `DataSource`:

   ```python
   from app.datasources.base import DataSource, RawRow, SourceError


   class BankApiSource(DataSource):
       code = "bank"  # попадёт в uploads.source и expense_records.source

       def __init__(self, client, date_from, date_to):
           self.client, self.date_from, self.date_to = client, date_from, date_to

       @property
       def label(self) -> str:  # название в истории загрузок
           return f"Банк {self.date_from}—{self.date_to}"

       def fetch(self) -> list[RawRow]:
           try:
               operations = self.client.operations(self.date_from, self.date_to)
           except ConnectionError as exc:
               raise SourceError(f"Банк недоступен: {exc}") from exc
           return [
               RawRow(
                   row=i, period=op.date, category=op.purpose, amount=op.amount, cost_center=op.unit
               )
               for i, op in enumerate(operations, start=1)
           ]
   ```

2. Передайте источник в общий конвейер — так же, как это делают файл и ручной ввод:

   ```python
   upload = imports.create_preview(db, user, "fact", BankApiSource(client, start, end))
   imports.confirm_upload(db, user, upload.id)
   ```

3. Добавьте эндпоинт или фоновую задачу, которая это вызывает, и подпись источника в `LABELS`
   ([app/web/common.py](app/web/common.py)). Модели и расчёты менять не нужно.

Рабочий минимальный пример — `SeedSource` в [app/seed.py](app/seed.py).

**Вход через Active Directory/LDAP** добавляется аналогично: реализуйте `AuthProvider`
в [app/auth/providers.py](app/auth/providers.py), зарегистрируйте в `PROVIDERS` и задайте `AUTH_PROVIDER` в `.env`.

## Технические решения

- **Деньги** хранятся целым числом копеек (тип `Money`): суммы точны и в SQLite, и в PostgreSQL.
- **PDF — ReportLab**: ставится через pip без системных библиотек. Шрифт с кириллицей берётся
  из системы (Arial на macOS, DejaVu/Liberation на Linux); свой шрифт — файл
  `app/static/fonts/DejaVuSans.ttf` или переменная `PDF_FONT_PATH`.
- **PNG — kaleido 0.2.1 + plotly 5.x**: не требует установленного Chrome.
- **CSRF**: токен в cookie сверяется с заголовком `X-CSRF-Token` или полем формы. Клиент API
  получает токен в ответе `POST /api/auth/login` (или `GET /api/auth/csrf`).
- **AI-анализ**: в Ollama уходят только итоги и топ-списки категорий, без отдельных операций.
  Для длинных периодов (больше трёх лет) ряд для AI укрупняется до кварталов.
  Сравнение двух периодов и план-факт остались только в API
  (`GET /api/analytics/comparison`, `GET /api/analytics/plan-fact`), страниц для них нет.
